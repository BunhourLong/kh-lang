2. `src/index.rs` — translation only, no segmentation logic. Rustdoc on every public
   item/field/method (napi-rs turns it into JSDoc, which spec #6 requires).
   - `#[napi(object)] pub struct Token { pub text: String, pub start: u32, pub end: u32 }`
     — doc that `start`/`end` are UTF-16 code-unit offsets.
   - Mode: `#[napi(string_enum = "lowercase")] pub enum SegmentMode { Bimm, Viterbi }`
     (or `#[napi(value = "...")]` per variant). Generated d.ts must expose
     `'bimm' | 'viterbi'`, not PascalCase. Default is bimm everywhere.
   - `#[napi(object)] pub struct SegmentOptions { pub mode: Option<SegmentMode> }`.
   - `#[napi] pub fn segment(text: String, options: Option<SegmentOptions>) -> Result<Vec<String>>`
     — top-level, embedded dictionary, token texts only, default bimm.
   - `#[napi] pub fn normalize(text: String) -> String` — wraps core `normalize`.
   - `#[napi] pub struct Segmenter` wrapping `kh_lang_core::Segmenter` plus whatever
     config is needed to rebuild it after `addWords` (e.g. mode + custom words).
     - `#[napi(constructor)] new(options: Option<SegmenterOptions>) -> Result<Self>`
     - `.segment(text) -> Vec<Token>` and `.split(text) -> Vec<Token>` — identical
       output; document `split` as an alias for spec compatibility.
     - `.insert_zwsp(text) -> String`.
     - `.add_words(words: <string[] | Record<string, number>>) -> Result<Self>`:
       mutates the receiver and returns a Segmenter so
       `new Segmenter().addWords([...]).segment(...)` chains (spec #5). Returning a
       cheap copy is fine; identity is not required. Do NOT return `void`. If napi-rs
       v3 genuinely cannot return `Self` from an instance method, STOP and report
       with evidence instead of silently dropping chaining.
   - `#[napi(object)] pub struct SegmenterOptions { pub mode: Option<SegmentMode>,
     pub dictionary: Option<Either<Vec<String>, HashMap<String, f64>>> }`.
     `dictionary` is ADDITIVE on top of the embedded dictionary (custom words), not a
     replacement. Same for `addWords`; duplicate word = last frequency wins.

3. Input validation (all JS-visible failures are `napi::Error` with a stable `.code`,
   never a panic; no unwrap/expect outside tests):
   - invalid/unknown mode or malformed options → `ERR_KH_OPTIONS`.
   - word that is empty, whitespace-only, or contains `\t`/`\r`/`\n` → `ERR_KH_WORDS`.
   - frequency not finite, `< 1`, or `> u32::MAX` → `ERR_KH_WORDS`; fractional values
     truncate toward zero.
   - use `napi::Error<S>` with a custom status type implementing `AsRef<str>` for the
     codes above (see napi-rs "Custom error codes"); implement `From<Status>` if the
     generated wrappers need it. Do not use `Env::throw_*` helpers.
   - arbitrary JS strings must not abort the process; a lone surrogate may convert to
     U+FFFD or throw a normal `Error`, but must not panic.
