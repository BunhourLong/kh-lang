## Test suite requirements (cover every acceptance criterion that is testable at JS level)

1. Exact: `segment("ខ្ញុំស្រលាញ់ភ្នំពេញ")` → `["ខ្ញុំ","ស្រលាញ់","ភ្នំពេញ"]`.
2. Losslessness: for a table of inputs (pure Khmer, Latin, digits, whitespace/punct,
   emoji incl. surrogate pairs, ZWSP U+200B, BOM U+FEFF, mixed, trailing coeng U+17D2,
   empty string, lone/unpaired surrogates) assert `segment(s, {mode}).join("") === s`
   for BOTH modes, and `normalize(s)` only removes ZWSP/BOM and never visibly changes
   anything else.
3. Default is `bimm`; `viterbi` is lossless. Build `test/fixtures/gold-100.mjs` with
   exactly 100 pure-Khmer sentences: each sentence is the concatenation of 2–6 distinct
   embedded-dictionary headwords, with `gold` boundaries known by construction. Verify
   in the test that `gold.join("") === text` and `gold.length >= 2`; check every gold
   token exists in `data/khmer.lbdict.txt` when generating the fixture. Compute
   boundary micro-F1 for both modes against gold over all 100 sentences and assert
   `f1(viterbi) >= f1(bimm)`. Do not weaken or delete this assertion; if it fails, first
   curate the fixture to remove genuinely ambiguous junctions (adjacent words that form
   a longer dictionary compound), not the assertion.
4. `split`/`segment` Tokens: `text.slice(start, end) === token.text`,
   `end - start === token.text.length` (UTF-16 units), offsets contiguous from 0 to
   `text.length`, and `.split` equals `.segment`.
5. `insertZwsp`: removing U+200B restores the input exactly; idempotent; does not insert
   next to Latin/digits/whitespace; pre-existing ZWSP preserved.
6. Custom words: constructor `{dictionary: [...]}` and `{dictionary: {...}}`, and
   `.addWords([...])` / `.addWords({...})` are additive, chain, and do not remove
   embedded words. Invalid words/frequencies throw `Error` with `.code === "ERR_KH_WORDS"`;
   invalid mode/options throw `.code === "ERR_KH_OPTIONS"`.
7. Arbitrary input never panics/aborts: deterministic corpus (fixed seed, no external
   deps) including malformed UTF-16 and high code points; each call either returns a
   lossless result or throws a normal `Error`; the process keeps running afterward.
8. Package surface: `require`-ability is not needed (ESM is fine), but assert the named
   exports `segment`, `normalize`, `Segmenter` exist and `Segmenter` instances expose
   `segment`, `split`, `insertZwsp`, `addWords`.
9. `index.d.ts` is shipped and contains the documented public types (light textual
   assertion is enough).

Use one `.test.mjs` file per concern if useful (e.g. `test/segment.test.mjs`,
`test/api.test.mjs`, `test/fuzz.test.mjs`, `test/gold-100.test.mjs`); `node --test test/`

## CI (`ci.yml`)

- `rust` job: ubuntu-latest, stable Rust with rustfmt+clippy, run
  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`.
- `node` job matrix: ubuntu-latest, macos-latest, windows-latest, Node 20, Rust stable;
  `npm ci`, `npm test` (self-contained build via pretest), `npx tsc --noEmit`.
- `pack` job: ubuntu-latest, Node 20, Rust stable; `npm ci`, `npm test`, then
  `npm pack --dry-run`, and assert the tarball contains `index.js`, `index.d.ts`,
  `README.md`, `LICENSE`, a `*.node` binary, and no `test/`, `.kh-lang/`, `target/`,
  or `node_modules/` entries.
- Use `actions/checkout@v4`, `actions/setup-node@v4` (npm cache), and
  `dtolnay/rust-toolchain@stable`. Keep it minimal; no third-party actions beyond these.
