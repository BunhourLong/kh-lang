2. `segment` pipeline:
   - Do **NOT** call `normalizer::normalize` inside `segment`; it drops ZWSP/BOM and
     would violate acceptance #2 (concat of tokens == original input, including ZWSP).
     Normalization stays a separate public API. Document this on `segment`.
   - Split with `run::runs`. For each `RunKind::Other` run: exactly one token.
   - For each `RunKind::Khmer` run: `matcher::bimm` or `matcher::viterbi` per mode;
     convert byte ranges to `Token`s (text + UTF-16 offsets).
   - Offsets are contiguous across the whole output: first `start == 0`, each next
     `start == previous end`, last `end == text.encode_utf16().count()`. Empty input →
     empty `Vec`. Never panic on arbitrary input (no unwrap/expect outside tests);
     u32 conversion may saturate but must not panic.

3. `insert_zwsp`: segment the input, then rebuild it inserting U+200B between two
   **adjacent** tokens only when the last char of the left token and the first char of
   the right token are both `RunKind::Khmer`. Never insert before/after `""`, at the
   string edges, or next to existing ZWSP/whitespace/Latin. Property:
   `insert_zwsp(s).replace('\u{200B}', "") == s`, and the call is idempotent.

4. Tests inline in `segmenter.rs` (no dev-deps), covering at least:
   - `ខ្ញុំស្រលាញ់ភ្នំពេញ` (default mode) → exactly
     `["ខ្ញុំ", "ស្រលាញ់", "ភ្នំពេញ"]`; no empty tokens; lossless.
   - Mixed `ខ្ញុំ Hello, 123! 🙂 ភ្នំពេញ` → lossless; the Latin/digit/emoji/space
     stretch is one `Other` token; UTF-16 offsets consistent with token text.
   - `ខ្ញុំ\u{200B}ស្រលាញ់\u{FEFF}ភ្នំពេញ` → lossless, ZWSP and BOM preserved in the
     output (they are `Other` tokens).
   - Same mixed/ZWSP inputs in `Mode::Viterbi` → lossless.
   - Builder: `add_word("ខ្ញុំស្រលាញ់")` makes `ខ្ញុំស្រលាញ់` one token;
     `dictionary(Dictionary::from_text("ភ្នំពេញ\t100\n"))` + `.mode(Mode::Viterbi)`
     yields one token for `ភ្នំពេញ` and remains lossless for unknown `ខ្ញុំ`.
   - `insert_zwsp`: `ខ្ញុំស្រលាញ់ភ្នំពេញ` gains ZWSP between Khmer words; removing
     U+200B restores the input; `abc 123` is unchanged; idempotent.
   - Empty string and whitespace-only input.
   - Deterministic pseudo-random property test (small LCG, 200 fixed cases, no external
     crates) over a pool with Khmer consonants/coeng/vowel marks, Latin, ASCII/Khmer
     digits, spaces, emoji, ZWSP, BOM: concat of tokens == input, offsets contiguous and
     consistent, no empty token text.
